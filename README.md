# Portfolio V3 project documents

This directory contains the current project documentation before the V3 codebase is bootstrapped.

## Documents

- `CONTEXT.md` - canonical domain language
- `STACK.md` - current technology stack and deliberately deferred technologies
- `docs/spec/portfolio-v3.md` - high-level product and architecture definition
- `docs/spec/portfolio-v3-implementation.md` - implementation-oriented specification
- `docs/development.md` - lightweight SDLC and development workflow
- `docs/adr/` - architectural decisions whose rationale is worth preserving

## Authority

`CONTEXT.md` is authoritative for terminology.

The product and architecture specification defines what the system is intended to become.

The implementation specification turns those decisions into practical engineering constraints.

ADRs explain why important architectural decisions were made.

`docs/development.md` defines the normal development lifecycle and completion standards.

The canonical vertical-slice progression is also defined in `docs/development.md`; it starts with the foundation, then Authentication + Projects as the first full-stack learning slice, followed by Inquiries, Media, Publishing/Preview, administration polish, the public visual experience, and production hardening.

## Ownership

Portfolio V3 is intentionally being implemented by its owner rather than primarily generated by a coding agent. The documentation exists to support deliberate engineering decisions, preserve domain language, and keep the architecture coherent as the implementation evolves.
