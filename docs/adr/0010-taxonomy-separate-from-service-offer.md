# Project taxonomy separate from the Service offer

Technology and Category classify Projects that exist; they do not advertise what the Portfolio owner can do or be hired for. Capability and service content belongs to separate concepts, introduced with the public showcase that needs them, rather than to the taxonomy tables.

The two sets genuinely differ. The owner can use technologies no published Project demonstrates, and may no longer offer work that an older Project is categorized under. Deriving a capability or services section from Project classifications would make advertising a skill impossible until work shipped with it, and would let unpublishing a Project silently withdraw an offer.

The alternative considered was one set of tables serving both jobs, which for a Portfolio of this size is fewer tables and less code. It was rejected because the presentation fields a showcase needs, such as description, icon, display order, and curation, would then sit on the Project picker, and any capability without a Project would become an orphan tag polluting it.
